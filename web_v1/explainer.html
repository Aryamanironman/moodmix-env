DJSet-v1 / approach

How the DJ agent works

This page explains every moving part: what the analysis measures, what the policy sees and controls, what the reward pays for, how it is trained, how the audio is rendered, and how to read the training records.

The pipeline

audio folder -> analysis_v2 (library_v2.py) beat grid, downbeat phase, phrase cues, per-beat bands / RMS / onset / percussion / harmony / centroid / vocal -> manifest_v2.json -> DJSet-v1 environment (env_v1.py) 41-float observation, 8 continuous controls, reward -> expert_v1.py (hand-written DJ) -> behavior clone (pretrain_v1.py) -> quiet clone (log_std -2.8) -> PPO fine-tune (train_v1.py) -> models/*.zip -> render_v2.py (beat warp, LR4 EQ, SVF filter, loudness, vocal ducking) -> local player (webapp_v1.py + web_v1) or scripts/mix_songs.py

The policy never sees a track id or a fixed BPM. It sees relative features, so a checkpoint trained on one folder can run on another. The local player scans a folder once, analyses it, and swaps the dropdowns to those songs.

1. Analysis: the beat grid is the foundation

The old version stored only a BPM. A real track's first beat is not at 0 s, and a tracker can report double the musical tempo. The analysis now stores the actual beat times, folds tempo octaves by subsampling the grid (choosing the offset with the strongest attacks), estimates the downbeat phase, and places phrase cues every 32 beats (eight bars).

This is a vocal likelihood, not a source separator. It is cheap enough to run on every beat. If your folder has .lrc files, the timestamps are used directly.

2. Observation: 41 numbers per beat

blocksizecontents
global4progress, remaining, crossfader, filter (normalized)
EQ state6deck A low/mid/high, deck B low/mid/high
deck A13low, mid, high, rms, onset, percussive, harmonic, centroid, vocal, bar energy, downbeat flag, bar position, phrase position
deck B13the same for the incoming deck
context5gain A, gain B, low-band overlap, tempo ratio, key distance

Everything is clipped to 0..1. The policy can see how far into the transition it is, which deck owns the low end, whether a lead vocal is present, and how far apart the two keys and tempos are.

3. Actions: 8 continuous controls

controlrangemapping
crossfader0..1equal-power: gain A = cos(pi/2 f), gain B = sin(pi/2 f)
EQ A low/mid/high0..1 each0 = -18 dB cut, 0.5 = 0 dB, 1 = +6 dB boost
EQ B low/mid/high0..1 eachthe same for deck B
filter (deck B)-1..1negative = low-pass sweep down to 200 Hz, zero = off, positive = high-pass up to 8 kHz

Beatmatching is automatic: both decks are on the same beat grid, so the policy spends its actions on the performance instead of on sync. Cue points are phrase starts chosen before the episode, with an option to search the strongest phrases for a demo.

Two reward games were found by measurement and closed: a parked fader was collecting continuity points, and PPO learned a three-beat cut because it avoided simultaneous playback. Continuity is now gated by blend time, hard cuts are charged, and mix quality requires a real blend.

5. Training: expert, clone, then PPO

Expert

A hand-written DJ follows one smooth fader arc, holds deck B's bass out of the first half, swaps the low end once around the midpoint, and releases a high-pass before the drop. It is the reference and the source of imitation data.

Behavior clone

400 expert episodes, MSE on the policy's mean action. The clone scores about 9.5 under the vocal-aware reward. It is saved with a narrow exploration sigma (log_std -2.8), because a wide sigma makes every PPO rollout a broken blend.

PPO fine-tune

Continuous PPO, 4 parallel environments, 32-beat episodes, gamma 0.99, clipped updates. The 1M-step vocal-aware run reaches eval +14.91, low overlap 0.116 and level jump 0.171, beyond the expert.

Records

Every run writes train_returns.csv, eval.csv, losses.csv, curves.png, report.html and report.md under runs/training/. The player's Training link lists them.

6. Rendering: from controls to audio

  • Beat indexing. Every position is a beat index into the real grid, not a guessed second.
  • Tempo match. Deck B is stretched by median(B beat) / median(A beat), then each beat is warped onto A's beat, so a 32-beat blend does not drift.
  • EQ. A three-way Linkwitz-Riley 4th-order crossover, with gains automated per sample from the action curve.
  • Filter. A two-pole state-variable filter with a smooth cutoff curve.
  • Level. Deck B is loudness matched to A before the fader; a slow master gain ride corrects macro level changes by at most 3 dB.
  • Vocals. When both lead-vocal curves are high, both mid/high bands duck; when only one is high, the other deck's mids duck under it. The low band is untouched.

7. Reading the metrics

metricmeaninggood direction
eval returndeterministic return on fixed seeds under the full rewardhigher
low overlapmean low-band overlap of the two decks; lower means one kick owns the low endlower
level jumpmean four-beat level change; lower is steadierlower
mix qualityterminal craft score, gated by blend timehigher
vocal clash / spacesimultaneous leads penalized, ducking creditedhigher space, lower clash
beat hitsfraction of the beat grid with an onset within 70 ms in the rendered filehigher, near 1.0
level p99 jump99th percentile of 250 ms RMS changes in the rendered filelower, under about 5 dB

In the curves, the training return is noisy on purpose: it is the sampled policy. The eval return is the deterministic mean and is the line to judge. Low overlap and level jump should fall together; if one rises, the policy is trading mud for a jump or the other way around.

8. Using it

Local player

python scripts/serve_v1.py --port 8050

Open the page, paste a music folder in the Library bar or use Browse, then Load folder. Each song is analysed once (about 15 s per song); afterwards the dropdowns are your songs. The model was trained on relative features, so the same checkpoint applies.

Command line

python scripts/prepare_library_v2.py --audio-dir "D:\Music" --out "D:\Music\manifest_v2.json"
python scripts/mix_songs.py --data-dir "D:\Music" --track-a "A.mp3" --track-b "B.mp3" \
  --model models/ppo_v2_final.zip --best-cues --out runs/v1/my_blend.wav

Training

python scripts/pretrain_v1.py --episodes 400 --data-dir crate
python scripts/train_v1.py --resume models/ppo_v2_bc_quiet.zip --timesteps 1000000 \
  --n-envs 4 --data-dir crate --device cpu --log-dir runs/training

9. Limits

  • The vocal signal is a heuristic, not a separator. It can flag a lead instrument as a voice. An .lrc sidecar is exact and overrides it.
  • The commercial 20-song crate is used locally. Audio and rendered mixes are not uploaded.
  • Beatmatching assumes a stable tempo. Beatless intros and odd meters can confuse the beat tracker.
  • Current techniques: phrase cues, bass swap, EQ, filter sweeps, vocal ducking, loudness riding. Loops, echo-outs and key shifting are not in the action space yet.
